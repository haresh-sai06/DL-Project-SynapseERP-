# Authenticated Generated Workspace API

The conversion pipeline now produces more than exported files. Every conversion can be opened as a protected ERP workspace with CRUD operations.

## Demo Authentication

Endpoint:

```http
POST /api/auth/login
```

Body:

```json
{
  "shop_id": "synapse-demo",
  "pin": "1234"
}
```

Response:

```json
{
  "access_token": "...",
  "token_type": "bearer",
  "shop_id": "synapse-demo",
  "role": "owner"
}
```

Use the token as:

```http
Authorization: Bearer <access_token>
```

## Workspace

```http
GET /api/workspaces/{conversion_id}
```

Returns:

- `inventory`
- `customers`
- `invoices`
- `analytics`

## CRUD Resources

Supported resources:

- `inventory`, keyed by `sku`
- `customers`, keyed by `name`
- `invoices`, keyed by `invoice_id`

List rows:

```http
GET /api/workspaces/{conversion_id}/{resource}
```

Add row:

```http
POST /api/workspaces/{conversion_id}/{resource}
```

Update row:

```http
PATCH /api/workspaces/{conversion_id}/{resource}/{item_id}
```

Delete row:

```http
DELETE /api/workspaces/{conversion_id}/{resource}/{item_id}
```

## Production Upgrade Path

The current implementation is intentionally local-demo friendly:

- Bearer token is HMAC-signed without external auth dependencies.
- Workspace state is stored as JSON under `outputs/workspaces/`.

For real SaaS deployment, replace this with:

- JWT/OAuth auth provider.
- Password hashing and refresh tokens.
- PostgreSQL workspace tables.
- Tenant isolation by shop/account.
- Audit logs for every human correction.
- Role-based access control for owner, staff, accountant, and auditor.
